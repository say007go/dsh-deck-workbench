# 设计与验收

> 本技能固定为 HTML 路线。文中 imagegen 内容仅用于说明设计边界，不执行、不询问路线、不切换。

## 风格稳定，主体随内容设计

先判断本次关系与信息量。HTML由Agent先取词删词并核验，再规划主体；imagegen接收完整原文、文字取舍规则、真实关系和参考风格，自由取舍原词并设计主体，不提前规定布局或预选上图文案。参考校准品质，不默认提供固定底稿。设计可原创，文字不因此获得改写权限。

稳定继承：16:9、纯白全页背景、黑色正文、单主色与平涂浅色、清晰字阶、标题体系、对齐与高信息密度。默认深红 `#AD0101`，用户有品牌要求则统一替换主色：HTML 改 CSS 变量，imagegen 在 `prepare_imagegen.py` 加 `--brand-color #XXXXXX`。局部浅灰或主色浅色块可以承载分组，不能变成全页底图或渐变底色。

内容载体默认是文字、信息图、关系图示及适量功能图标。除非用户明确要求，不用照片、场景插画、汽车/工厂/人物/山水等配图、纹理或装饰性背景；参考页偶有这些素材也不继承。图标须辅助识别内容，不能用一排图标代替逻辑图示。

为后续转成PPT，图形采用清晰的二维平面表达：轮廓闭合、边界锐利、线条清楚、连接与分组可辨、纯色平涂。可组合原生几何构成复杂信息图，不以渐变、阴影、光效、立体透视、浮雕、模糊叠化或融成一团的半透明形状承载关系。文字、线与图形视觉上可区分，箭头与连接不压字。验收时判断关键形状和层级能否用普通PPT对象逐一重建，但不声称生成图片本身具备对象或可编辑性。

自由变化：主体分区、宽高比例、图示类型、说明位置、段落图示组合和重点。没有固定三栏四栏；相同内容关系可保持结构一致，不为求新改逻辑。

HTML标题可采用参考中的浅灰带、主色短竖线和黑字，章节名与具体主题分字重。imagegen只要求标题层级清楚、整体风格一致，不指定标题所在位置或标题带几何。全部文字来自本次输入，长标题不靠改写或硬压字号解决。

总领段用完整原句承接主体，按需强调原词。主体以内容图示、段落、清单和真表格表达关系；不是每页都强迫文字图形化。连接、色块、分支、交集和层级都应有信息意义。

以下数值仅用于HTML：1920×1080 CSS画布下，参考12pt约对应24px视觉尺度。可从正文24–30px、说明22–26px、模块标题28–34px、页标题44–56px起步，按本页及实际参考调整，不当全库固定参数。默认实质正文不低于24px。imagegen只要求清晰可读的字阶，不传精确字号、坐标或区域比例。两条路线都不能继承原稿小字或裁切。

## 关系家族

| 标签 | 表达方法 | 语义限制 |
|---|---|---|
| mapping | 层级挑战启示对应、输入输出对应 | 不将多对多强画一对一 |
| flow / timeline | 路径、台阶、时间轴、交错说明 | 有先后才能加箭头，等距不代表等时长 |
| matrix | 阶段×任务、对象×内容、渠道×职责 | 维度来自原文，不补空栏目 |
| hierarchy / model | 梯队、分层、交集、核心与维度 | 大小位置和交集均有含义 |
| network | 协作、汇聚、中心辐射 | 不为复杂而添加无依据连接 |
| comparison | 双对象、前后、两种路径 | 比较真实可比维度，不虚构同构文字 |
| cycle | 反馈、复盘、优化循环 | 没有回流就不画闭环 |
| parallel / narrative | 多项重点、分层长文、图文互释 | 不默认卡片墙，按长短分配空间 |
| evidence / outcomes | 实物解读、成果分组、方法样例 | 只用本次证据，不挪用历史客户截图 |
| hybrid | 矩阵加并行路径、模型加对应说明 | 主阅读方向清晰，不能拼成多个无关小页 |

这些是检索标签，不限制原创。许多参考页有多种组合关系，layout_note和relations比单一主标签具体。

## 多样性

HTML可借一页的阶段主线和另一页的角色分工，再按内容重组。imagegen只借视觉语言与信息表达品质，不指令采用某种阶段主线、角色图、矩阵、金字塔等具体形式，不能把本节关系家族当成生图版式菜单。只有用户明确要求某种图或复刻时，其指示才覆盖自由布局默认。

连续相同骨架时检查内容是否确有需要；变化可以发生在阅读方向、区域比例、说明组织和关系组合。方框换圆形不算真正结构变化。不采用固定轮换表，不为配额强换形式。

## 参考效果怎样落实

不是只存入整库图片或提取深红配色就算调用参考。制作时从全库检索，按本页内容关系、文字量和图文表达需要选候选，实际看清晰图；不因业务词相似就选不适合的页面，也不默认每页都用同一组风格图。

- HTML：从候选中理解标题、总领、主体的层级，段落与图示的结合、对齐、留白、信息组织和适用结构，按当前文案重组。允许组合不同参考的表达方法，但每个图形必须承载本页信息，不复制历史内容或截图。
- imagegen：传入1–3张本次看过的真实参考图片，文字说明它们代表的单色视觉语言、图文融合、信息密度、层次与完成度。不能只传页码、路径字符串或泛称“咨询风”；不给它参考的几何数据和固定构图要求。参考可启发品质，不要求复制分区，也不因自由设计而放弃对标。
- 验收：实际成品与选定参考图并排看，逐项比较信息层级、图示解释力、图文对应、可读密度、空间利用、视觉精细度与多页变化。在reference-choice.json记录参考用途及具体差距；内部截图或原生生图均须实际查看，不能用程序通过、自评分或“风格接近”代替判断。DSH 默认沙箱下不能起浏览器截图；按 [DSH 集成](dsh-integration.md) 申请一次更宽权限，或请用户在侧栏/浏览器查看，未看图时如实说明。

参考不是模板：能指出参考的具体处理（标题与导语关系、分组和阅读路径、色彩角色、字阶、密度、装饰）怎样影响了本页，而不只是“参考了某页”。如果成品骨架与参考相近，先判断是内容关系需要，还是参考的默认；内容需要可以保留，参考默认则重做或如实说明。用户明确要求创新时，不静默选择最稳方案，至少说明一个认真考虑过的不同方向及取舍；不强制数量、不强制结构差异，也不为“看起来不同”加装饰。表格、矩阵或叙述式都可以是正确答案，关键是结构由本页内容支持。

若成品只是整齐堆字、整页同构卡片、空泛图标或靠过小文字提高密度，回到本次内容和参考定位具体问题：HTML调整结构和字阶，imagegen以具体质量问题定向修正而不补一套固定版式。未达到时继续合理修正或如实报告差距，不能因已交付文件就宣称达到参考。不同原文信息量、工具生成误差和参考渲染细节会影响结果，不无条件保证所有页面一次达到同等质量。

## 验收门槛

硬门槛：文字有出处且无改写，实质内容覆盖，数字条件准确，无历史残留，逻辑关系正确，16:9，无文字溢出、遮挡和难辨小字。

看实际成品整页（PNG/WebP 或 HTML 渲染）并放大密集文字区和连接处，与最相关参考图并排比较：主次与阅读顺序、关系图解释力、图文对应、密度及空间分配、同级对齐与字号、单色体系、标题层级、主体是否服务当前内容。不能用程序通过或自评分代替看图，不要求像素相同。没有截到图时，明确写出“未做像素级验收”，不要声称看过。

迭代根据实际问题进行。反复仍无法兼顾重要原文与可读性时，明确说明冲突，让用户决定分页或删减，不静默降低标准。
