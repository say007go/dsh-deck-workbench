# ppt-layout

## 工作流程

1. 解析参考库（`assets/build-kit/reference_root.py`）：优先 `--reference` / `DECK_REFERENCE_ROOT` / `~/.dsh/storages/deck-workbench/reference.json`，参考稿为 `<参考库>/assets/reference.pptx`。本技能包不内置参考稿副本；共享库不可用时明确报错。参考稿保持原样；在工作区制作新稿。
2. 先读 [设计规则](references/design-rules.md)、[页面选用指南](references/page-guide.md) 和 [快速路径](references/quickstart.md)。设计规则含借鉴层级判据与内容依据红线，优先于任何模板惯例。
2b. **动手前先跑一次规格速查**：`python assets/build-kit/probe_spec.py --page N` 一条命令读出参考页的配色、字体、标题几何与字号、导语规格、段落样式、字阶、项目符号、构件语汇与形状清单（省略参考稿路径时自动解析共享参考库）。凭印象猜参考稿长什么样是返工的头号来源。
2c. **先确认依赖**：`python assets/build-kit/check_deps.py` 一条命令体检（解释器、python-pptx／lxml／Pillow／pymupdf、LibreOffice、中文字体、参考稿），缺什么给什么修法；末尾还做**可移植性自检**——扫出包内所有写死的本机路径（`.py` 的字符串常量、`.md` 代码围栏内的命令）。工具**不写死本机路径**：LibreOffice 与字体目录都是先探测再调用（`PPT_SOFFICE` / `PPT_FONT_DIR` 可覆盖）。
3. 为每个目标页先确定要表达的关系（阶段递进／并列比较／因果／角色协作／层级／闭环／多维交叉），再选择直接复用、组合改造或自由创作。三种方式均已获用户同意，日常选版无需再次确认。
4. 找参考页用结构检索而不是逐页翻：`<参考库>/references/page-signature.jsonl` 收录参考页的客观几何签名，`assets/build-kit/scan_parts.py` 可按连接件数量、列／行组数、几何形状筛选，并导出候选页的零件规格表。签名缺失时先用构建器重建参考库；命中页再渲染目视确认。
5. **借鉴层级**：默认继承视觉语言（配色、字体、标题体系、字阶、信息密度），零件级借用几何规格（见 [零件目录](references/parts-catalog.md)）；**不默认继承整页骨架**。判据：把本页内容替换成任意其他主题后仍然成立的骨架就是通用骨架，必须为本页重新设计信息秩序。整页复用仅在用户明确要求复刻，或内容关系与候选页确实同一时使用。
6. 出页用 `assets/build-kit/pptx_kit.py`：继承母版与版式、生成新页、度量与溢出预检、受控断行、中文引号处理、单页瘦身、渲染链。工程确定性的部分交给工具，**关系判断与版面创造仍由内容决定**。
7. 复核用 `assets/build-kit/audit.py` 一条命令跑完**八道关**：包完整性、文本层审计、**字号层级跨页一致性**、导语净空、**文本框纵向溢出**、渲染 PDF 与 PNG、切成分区放大图、**构件语汇一致性**；多页 deck 用 `--all` 逐页跑。**分区图必须逐张目视**——静态检查全绿不等于视觉正确。改动工具后先跑 `assets/build-kit/selfcheck.py`（7 项自检，含**门禁有效性自证**：造 5 个已知形态的文本框验证溢出门禁既不漏报也不误报，含一条**轻度溢出 17%** 的灵敏度锁）。
   **第 5 关的判据是「文字越出视觉容器的外框」**：需高按**真实渲染行高**折算（字号 × 行距 × 1.20，无行距按 1.0 算），文字形状自带填充/描边时它自己就是容器，纯文本框则取外层最小的卡片作容器——内边距只是留白，越过内边距不算缺陷，越过卡片下边框才算。
8. 交付「一份 N 页方案」时用 `assets/build-kit/merge_pages.py` 把逐页打磨好的单页按顺序合并（保留母版／版式／主题）；合并后必须重跑 `audit.py --all` 复核——合并会重建页面，标题与几何可能被改动。
9. 以用户需求、客户资料及已确认文案为内容依据。历史客户名称、指标、年份、课程、师资、费用及服务时限不得作为当前项目事实继承；参考稿是页面资料库，其页数和排列顺序不是新稿的页数或章节要求。
10. 交付前确认页面内容覆盖、逻辑关系、文本溢出、对齐、信息密度与整体风格一致，且无参考稿残留。

## 继承什么／不继承什么

本技能的**主线是复刻参考稿的页面设计**。以下内容从参考稿实测继承，不写死：

- `open_reference()` / `open_deck()` 打开参考稿时自动装载其调色板（主题 accent1/accent2、正文字体、描边灰、浅底色）到模块级 `PALETTE`，之后 `add_arrow()` / `add_strip()` / `add_chip()` 等造型原语自动使用参考稿自己的颜色。
- 标题的位置与高度**继承参考页原值**，宽度按版式标题带可用范围放宽；字号优先继承参考页标题（无显式字号时从版式 `lstStyle` 读继承字号）。
- 导语框的位置、宽高、边距、字号、字体、颜色由 `probe_lead_spec()` 从参考页实测得出；新建页用 `add_lead_box()` 按同一规格补齐。
- **段落级样式也是继承项**：悬挂缩进、行距、项目符号（颜色／字体／字符）由 `probe_para_style()` 读出，由 `apply_para_style()` 原样写回。只搬 run 会丢掉这些，导致新建页与继承页一眼就不一样。项目符号规格由 `probe_bullet_style()` 单独探测。
- **字阶也是继承项**：`probe_type_scale()` 从参考页读出字号谱与档位。字号层级与配色、字体同级，都是视觉语言的一部分。
- **构件语汇也是继承项**：参考稿自己用哪些形状比例（方块／扁横条／横块），由 `probe_part_vocab()` 实测得出。只继承配色与字号、却自创出参考稿里没有的形状（例如「卡片左侧贴一根实心色条」），一眼就是外来套路。`audit.py` 第 8 关「构件语汇一致性」按此拦截。
- **标题的**结构**也是继承项，不只是字号**：参考页标题是一段（单行大字）还是两段（主标＋副标），由 `probe_title_spec()` 实测得出（`has_sub`）。给单段标题的参考稿凭空补一个副标，会多出一段文字并影响行高与基线。
- **度量字体也是继承项**：度量（`text_width_in` / `fit_check` / `wrap_manual`）默认用参考页真实使用的正文字体（`METRIC_FONT`，由 `load_palette()` 装载）。用雅黑度量宋体或等线排版的稿，英文与数字宽度会偏 10% 以上，换行点与实际渲染对不上。
- 标题与导语的识别不依赖「标题必须是占位符」——占位符或普通文本框都能处理；参考稿标题不是占位符时，新建页由 `add_title_box()` 按实测规格补建。

**不继承的是整页骨架**：把本页内容替换成任意其他主题后仍然成立的骨架，就是通用骨架，必须为本页重新设计信息秩序。

**参考页的选择**：默认复刻参考稿第 1 页（`keep=1`），行为稳定。若参考稿以封面开篇，封面的大标题会被误当成导语框——此时显式传 `keep=N` 指定要复刻的正文页；`pick_reference_page()` 可按版式分组自动挑典型正文页（多数版式的那一页）。

## 骨架规格只有一个装载入口

`open_reference()` / `open_deck()` 打开参考稿时，除了调色板与项目符号，还会把**页面骨架规格**装载到模块级 `LAYOUT`：

| 读什么 | 从哪来 |
|---|---|
| `LAYOUT['title']['top' / 'height' / 'size_lead' / 'has_sub']` | 参考页标题实测 |
| `LAYOUT['lead']['top' / 'height' / 'size']` | 参考页导语实测 |
| `LAYOUT['body']['top' / 'bottom' / 'left' / 'right']` | 参考页内容区实测 |
| `LAYOUT['scale']['title' / 'body' / 'label']` | 参考页字号档位实测 |
| `PAGE_BOUNDS['l' / 'r']` | 参考页版心左右缘实测 |

**为什么必须是单一入口**：此前每张出页脚本各自手写标题／导语的 `top`／`height`，参数彼此不一致——同一份 deck 里有的页传了、有的页漏传，导语因此漂移 0.147"，第二行被下方条带裁掉。根因不是某张页写错，而是**没有单一权威源**。

出页脚本统一从这里取坐标，不要各写各的。参考稿变了，`LAYOUT` 跟着变，不需要改脚本。

> `PAGE_BOUNDS` 与 `LAYOUT` 是**可变容器**，用 `from pptx_kit import *` 引入后拿到的是**同一个 dict 引用**——直接 `LAYOUT['x']` 读取即可，不要 `LAYOUT = {...}` 重新赋值（重新赋值对调用方无效）。这与 `PALETTE` 是同一个坑。

## 字号层级必须跨页一致

同一份 deck 里，若某页正文用了比其它页更小的字号，静态检查全绿、渲染也「看着能过」，但整份放在一起字阶就散了。`audit.py --all` 会做**页与页之间**的比较：统计每个字号出现在多少页上，多数页共有的档位即为常规档位，少数页特有且更小的档位会被逐条列出。

自测已验证双向：故意改小的一页被准确检出并列出文本；单页 deck 不自比、不误报。

## 窄栏排版

窄栏（多列卡片）里自动换行会把词拆断（"检查"断成"检"／"查"）、行末常剩孤字。**根治写法是从文案层就写成行数组**，交给 `add_textbox(..., {'lines': [...]})` 逐行独立排布，而不是写长句指望自动折行。

## 适用边界

本技能负责页面的视觉与组织，不预先决定内容事实。用户本次明确要求优先于参考稿惯例。参考文件保留历史内容用于理解版式；新稿的事实须重新核实。

`assets/build-kit/` 提供通用工具，不含任何项目内容、案例或内置词表。残留词检查的词表须按本次内容依据临时传入。
