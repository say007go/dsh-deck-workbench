# 快速路径

一页 PPT 的最短可复现流程。设计判断在前，工具在后——工具负责「不返工」，
不负责「替你想」。

**本技能不预设版式**：配色、字体、标题几何、导语框规格全部从参考稿探测。
换一份风格不同的参考 ppt，同一套代码照样能用。

## 0. 先确认解释器与依赖（30 秒，别跳过）

**一条命令体检**（只报告、不安装）：

```bash
python assets/build-kit/check_deps.py
```

它会逐项列出「有什么、缺了会怎样、怎么补」。下面这张表是同一份清单：

| 依赖 | 必需? | 用途 | 缺失后果 |
|---|---|---|---|
| **Python 3.7+** | 必需 | 跑全部工具 | — |
| `python-pptx` | 必需 | 读写 pptx | 所有脚本 `ModuleNotFoundError: No module named 'pptx'` |
| `lxml` | 必需 | 解析/改写 pptx 内部 XML | python-pptx 的依赖，装上 python-pptx 即自动带上 |
| `Pillow` | 必需 | 字体度量（算文字宽度、折行、溢出预检） | 文字宽度算不出来，度量函数全报错 |
| `pymupdf` | 必需 | PDF→PNG 渲染与分区裁切（审计第 6、7 关） | 渲染关卡无法执行 |
| `numpy` | 可选 | 仅 `measure_text_bands()` 像素字带测量 | 该函数不可用，其余不受影响 |
| **LibreOffice**（`soffice`） | 必需 | pptx → pdf（审计第 6 关） | 渲染关卡无法执行 |
| **中文字体** | 必需 | 度量用（本机探测，找得到就用） | 文字宽度算不出来 |
| 参考库中的 `assets/reference.pptx` | 必需 | 用共享参考库出页；本包不内置副本 | 未配置参考库时需用户提供或先用构建器建库 |

**不写死本地路径**：LibreOffice 与字体目录都是**先探测、再调用**——

- LibreOffice：环境变量 `PPT_SOFFICE` → 各平台常见安装目录 → `PATH` 里的
  `soffice`/`libreoffice`。找不到会报出可读的错误并告诉你设哪个环境变量。
- 字体目录：环境变量 `PPT_FONT_DIR` → Windows 系统目录 → 用户字体目录 →
  macOS/Linux 常见目录。参考稿的字体在任一目录里找不到就回落本机中文字体
  并告警一次（宽度可能偏大，换行点对不上）。

**开跑前先探一次**，别用「装好了」的假设：

```bash
python -c "import pptx, fitz; print('OK', pptx.__version__)"
```

报 `ModuleNotFoundError` 就**换解释器**，不要就地往默认 `python` 里装包——
某些环境下默认 `python` 指向的是隔离的空解释器（工具自带的托管运行时），
往里装包会污染它、且该环境未必有写权限。

正确做法：**先找出哪个解释器已配好依赖**，再显式用它的完整路径。
下面用 `<解释器>` 占位，请替换成你查到的那个（用 `where python`（Windows）/
`which -a python`（macOS·Linux）/ `py -0p` 列出候选，逐个试）：

```bash
<解释器> -c "import pptx, fitz; print('OK')"
```

装包时也只往这个解释器装（Windows 需提权）：

```bash
<解释器> -m pip install python-pptx pymupdf Pillow
```

本文档后续命令一律写 `python`——指的是**你已确认可用的那个解释器**。
脚本里也建议用绝对路径调用，避免在不同 shell 下解析到不同解释器。

### 一条命令做完整体检

```bash
python assets/build-kit/check_deps.py
```

除依赖清单外，末尾还做**可移植性自检**：扫出包内所有写死的本机路径。

- `.py` 扫**字符串常量**（用 AST 解析，自动排除注释与 docstring 里的反例说明）
- `.md` 只扫**代码围栏内**——围栏里的命令会被照抄执行，围栏外的散文是在讲这件事

命中就报文件与行号。**别在示例里写死本机路径**，用 `<解释器>` 之类的占位符；
真要指向某个目录，就走环境变量（`PPT_SOFFICE` / `PPT_FONT_DIR`）或相对本技能目录的相对路径。

## 1. 先定关系，再找参考

本页要表达的是什么关系？阶段递进 / 并列比较 / 因果 / 角色协作 / 层级 / 闭环 /
多维交叉。关系定了，骨架才定。

## 2. 按结构检索参考稿，而不是逐页翻

`<参考库>/references/page-signature.jsonl` 收录参考页的客观几何签名（列组数、行组数、
连接件数量、卡片数量、红色块数量、字号谱）。用它做候选筛选：

```bash
cd <技能目录>/assets/build-kit
python scan_parts.py --find arrows --min 3     # 含 ≥3 个连接件的页
python scan_parts.py --find cols   --min 4     # 含 4 列等宽卡片组的页
python scan_parts.py --find geom --geom chevron
python scan_parts.py --spec 116               # 导出某页的零件规格表
```

命中页再渲染缩略图目视确认。参考稿页数多时全靠肉眼翻是最大的时间黑洞，
签名索引把它压到几十页。

## 3. 取件而非取页

用 `--spec` 看中的页的零件几何，挑**零件**（箭头比例、条带圆角、卡片描边），
不要照搬整页骨架。判据见 `design-rules.md` 的「借鉴层级」。

## 4. 出页

**单页**：

```python
import sys
sys.path.insert(0, r'<技能目录>/assets/build-kit')
from pptx_kit import *
from reference_root import resolve as resolve_reference

REFERENCE = str(resolve_reference(None, ('assets/reference.pptx',), r'<技能目录>') / 'assets/reference.pptx')

prs, slide = open_reference(REFERENCE, keep=1)   # 继承母版/版式，裁到单页
lead = find_lead_box(slide)                      # 导语不是占位符，先取出
clear_body(slide, keep_ids={lead.shape_id})      # 清正文，保留标题与导语
setup_title(slide, '«章节名：»', '«本页主题»')
setup_lead(lead, '«导语»')

# …按本页关系搭建主体…

save_and_report(prs, OUT)
```

**取色顺序是硬规则**：`pal()` 只能在 `open_reference()` / `open_deck()` **之后**
调用——调色板是运行时从参考稿装载的，打开之前取色拿到的是内置参考稿的颜色，
换一份不同色系的参考库就会出「同页红蓝混排」。现在提前取色直接抛
`RuntimeError`，报错信息里写明该把哪一行挪到后面。

```python
NAVY = pal('accent')                    # ✗ 参考稿还没打开
prs, slide = open_reference(REF, keep=2)

prs, slide = open_reference(REF, keep=2)
NAVY = pal('accent')                    # ✓ 打开之后再取
```

`RED` / `RED2` / `TINT` 这些常量是**内置参考稿**的实测值；要跟随当前参考稿，
颜色一律走 `pal()`。

**整套方案（多页）**——交付形态是「一份 N 页 pptx」，不是 N 个单页文件：

```python
prs, slides = open_deck(REFERENCE, pages=5)      # 铺成 5 页空白 deck
for i, slide in enumerate(slides):
    lead = find_lead_box(slide)
    clear_body(slide, keep_ids={lead.shape_id})
    setup_title(slide, '«章节名：»', '«本页主题»')
    setup_lead(lead, '«导语»')
    # …按本页关系搭建主体…
save_and_report(prs, OUT)
```

`open_deck` 的新增页复用**参考页自身的版式**，并按 `probe_lead_spec()` 探测到的
规格补一个导语框，因此每页的视觉体系（灰带、红竖条、标题带）与继承页一致。

`open_reference` 会自动：删掉其余页、移除 think-cell 残留、清理孤立关系，
成品体积自动落到几十 KB 级，不需要手工瘦身。

导语框必须先 `find_lead_box` 取出再 `clear_body`，否则会被当正文清掉。

### 4a. 逐页打磨 → 合并成一份 deck

若按「单页迭代」的节奏做页（每页单独渲染目视），交付时用 `merge_pages.py` 合并：

```bash
python merge_pages.py --out 方案.pptx 页1.pptx 页2.pptx 页3.pptx 页4.pptx 页5.pptx
```

基底取第一个 pptx（保留母版／版式／主题），后续每页沿用同一 layout 新建并搬入
源页形状。合并后**必须重跑 `audit.py --all`**：合并会重建页面，标题文字与标题框
几何都可能变（`merge_pages` 已专门搬这两样，但复核不能省）。

## 4b. 风格自动跟随（换参考稿也成立）

打开参考稿时会自动装载其调色板与字体到模块级 `PALETTE`：

```python
prs, slide = open_reference(REFERENCE, keep=1)
print(PALETTE)     # {'accent':…, 'accent2':…, 'tint':…, 'line':…, 'font':…}
```

之后 `add_arrow()` / `add_strip()` / `add_chip()` 的默认色都取自 `PALETTE`，
无需在脚本里写死颜色。标题字号继承参考页（无显式字号时从版式 `lstStyle` 读），
导语的字号字体颜色位置由 `probe_lead_spec()` 得出。

**段落级样式也跟随**：悬挂缩进、行距、项目符号（颜色／字体／字符）由
`probe_para_style()` 读出，`add_lead_box()` 建新框时用 `apply_para_style()`
原样写回。只搬 run 会丢掉这些，新建页与继承页一眼就不一样。

```python
spec = probe_lead_spec(slide)
print(spec['para'])
# {'marL': 285750, 'indent': -285750, 'line_spacing': 1.5,
#  'bullet': '', 'bu_color': 'AD0101', 'bu_font': 'Wingdings', …}
```

项目符号的字符是**私用区字符**（Wingdings 方块），不是十进制数字串——
原样搬 `a:pPr` 原文最稳，不要自己重建。

## 5. 复核（一条命令）

```bash
python audit.py --pptx <成品.pptx> --forbid 词1,词2        # 单页
python audit.py --all --pptx <多页方案.pptx> --forbid …     # 整份 deck 逐页
```

依次完成九道关：包完整性 → 文本层审计（残留词／ASCII 直引号／U+FFFD）→ **字号层级
跨页一致性** → **导语净空**（压线／重叠／纵向溢出）→ **文本框纵向溢出** →
渲染 PDF 与 150dpi PNG → 切成 4 张分区放大图 → **构件语汇一致性** → **主色同族校验**
（成品里是否混入 kit 内置默认红 AD0101／C00000／FCF4F4，即「提前取色」的指纹）。`--all` 会逐页做文本审计、渲染 `audit_pN.png` 并把分区图放进
`pN/` 子目录。**分区图必须逐张看过**——静态检查全绿不代表视觉正确，孤字行、压线、
错位只有肉眼能发现。

字号层级那一段做的是**页与页之间**的比较：统计每个字号出现在多少页上，多数页共有的
档位即常规档位；某页出现少数页特有且更小的档位时，会逐条列出是哪几处字太小。
单页 deck 不自比、不误报。

导语净空那一段做的是**纯几何**判定：找出标题下方最近的通栏文本框当导语，比对它
底边与下方元素顶边的间距（小于 0.05″ 视为压线），再算文字实需高度是否超框高。
导语位置若靠继承参考页原值，某页下方元素一挪就会压线——这一关就是替眼睛盯着它。

`--forbid` 的词表按本次内容依据临时指定：历史客户名、指标、年份、课程、师资、
费用、服务时限等不得继承的内容。工具不内置任何项目词表。

### 5b. 客观验收：像素字带测量

「这段是不是折成了两行」「行距是否正常」可以变成可回归的数字，不必只靠肉眼：

```python
from pptx_kit import measure_text_bands
b = measure_text_bands('audit_p2.png', dpi=150, y0=0.0, y1=1.05)
print(len(b), b)      # 标题带 1 行 = [(0.373, 0.827)]；2 段 = 折行了
```

取灰度暗像素行、合并间距小于 3px 的相邻段，每段即一行字。用于：确认标题带只有
一行、确认窄栏各行行距一致、确认没有叠印（单段高度异常大）与空行（段间大空隙）。

## 6. 生成阶段就把溢出挡掉

出页脚本里直接调预检，不要等渲染后才发现：

```python
fit_check('导语', LEAD, 14, 11.7, 0.68, ls=1.5)
lines = wrap_manual('长句……', 11, 2.8)   # 受控断行，避免词中断开
orphan_check('终点块', lines, 11, 2.8)    # 末行孤字检测
```

`fit_check` 按**真实渲染行高**折算（字号 × 行距 × 1.20，无行距按 1.0 算），
与 LibreOffice 实测一致——用 1.15 会低估 4%，窄框里正好是「末行被切一半」的那一刀。

长句放进窄框时，优先用 `wrap_manual` 预先拆行，再把每行放进独立段落，
不要依赖自动换行——自动换行会在词中间断开。

**最直接的写法是让文案层就写成行数组**，再交给 `add_textbox` 的 `lines`：

```python
add_textbox(slide, x, y, CW, 0.62, [
    {'runs': [('', 10.5, True, BLACK)], 'lines': ['从「专业贡献者」', '变为「团队负责人」'], 'ls': 1.14},
])
```

每行独立成段，既不会断词也不会出孤字行。纯文本块（无项目符号）续行与首行左对齐；
项目符号段落走 `bullet_para(lines=…)`（续段 `buNone` + 悬挂对齐）。

**别忘了量横向边界**：多列卡片最容易越出内容区右边距。把列宽按
`(内容区宽 − (列数−1)×间隙) ÷ 列数` 算出来，并在脚本里自检每块的左右缘。

## 7. 交付前查骨架撞车

同一套方案的各页骨架不应重复。只看客观几何，不看配色：

```bash
python scan_parts.py --skeleton 页1.pptx 页2.pptx 页3.pptx
```

输出各页的行数、每行块数、连接件数，并两两比对。**零件层（配色／圆角／字号）
完全不参与判定**——多页共用同一批零件是正常的，不该被判成撞型；只有骨架
（分几栏几行、块的排列、连接件拓扑）相同才算撞型。

判定距离 < 阈值（默认 0.85，越小越敏感）即判撞型并报出距离。

### 4c. 减色：信息编码一次就够

页面上每个小色块都在向读者「喊话」，喊得越多越没人听得见。排版减色的
判据不是「好看不好看」，而是**「删掉它，信息会丢吗」**：

- 同一信息被编码两遍以上 → 保留最强的那一处，其余降级为文字或留白；
- 文案已经说清的归属/层级 → 不再叠加颜色标记（颜色是给「读不出来」的东西用的）；
- 颜色承担**识别**职能时，必须是描边色之外的高对比色（浅灰描边色当识别色＝看不见）；
- 同类色块排序后能连成段，就排；连不成段就换成文字标签；
- **窄色条（宽 0.035"~0.12"、高 ≥0.25" 的实心条）是外来套路高发区**：
  参考稿正文区全稿仅个位数、单页上限 2 根。发丝级（≤0.03"）分隔线则合法；
- 凡是「线」，一律用 `add_connector()` 或 `shape.line` 画，不要拿实心细条冒充。

## 常见坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| LibreOffice 报 `source file could not be loaded` | Windows 反斜杠路径 | 用 `file:///` URL（`pptx_kit.file_url`） |
| PowerPoint 打开提示「需要修复」 | `a:pPr` 子元素顺序错 | 按 `_PPR_ORDER` 插入 |
| 引号周围多出空隙 | 用了 ASCII 直引号 | 走 `cn_quotes`，中文用 `“ ”` |
| 词被断成两行 | 自动换行 | 用 `wrap_manual` 预拆行 |
| 项目符号段落行间多出整行空白，或续行与首行叠印 | 用了 `<a:br/>` | 改用 `bullet_para(lines=…)`（首段带符号＋续段 `buNone` 悬挂对齐） |
| 成品几十 MB | 未裁剪参考稿 | `open_reference` + `clean_orphan_rels` |
| 红色竖条／灰带丢失 | 新建空白页而非继承版式 | 用 `open_reference` / `open_deck` 而非 `Presentation()` |
| 新建页没有导语框 | `add_slide` 只带标题占位 | 用 `open_deck`（自动按参考页规格补导语框） |
| `find_lead_box` 返回 None | 参考页导语是空框 | 先 `open_deck` 补框，或给参考页导语写入文字 |
| 标题字号突然变大 | 标题 run 无显式字号、探测跳过了它 | `setup_title` 已处理：从版式 `lstStyle` 读继承字号 |
| 标题末尾掉字换行 | 标题框宽度不够 | 宽度按版式标题带可用范围放宽；必要时改短文案 |
| 改了 kit 后新旧渲染对不上 | 只重建没重渲染，比的是旧图 | 重建后必须重跑 `audit.py` 再比 |
| 参考页的图片/曲线叠在新页内容下 | `clear_body` 按形状名字前缀删，只认英文命名 | 按「有无内容」判定；含图片/组合一律删
| 空框盖住新页文字 | 纯色块一律保留，正文区的空容器框也留下了 | 只保留与标题框/导语框重叠的装饰
| 导语第二行被下方条带裁掉 | 导语位置靠继承，下方元素位置一变就压线 | 导语位置显式声明；`audit.py --all` 的净空关会报
| 合并后第2页起全丢标题 | 搬形状时跳过了标题占位 | 合并器把源页标题段落补进目标页占位符
| 合并后标题又折行 | 丢了建页时的标题框加宽 | 合并器把源页标题的 `a:xfrm` 一并搬过去
| 审计报「第2页/第8页」而实际只有2页 | 按 `slideN.xml` 的 N 当页号，裁剪后编号不连续 | 用 `Presentation.slides` 真实顺序；文本层取 slide part 的 blob
| 调色板看着没跟着参考稿变 | `PALETTE = new` 重新绑定，`import *` 拿到旧引用 | 装载时原地 `clear()+update()`
| 项目符号永远是红圆点 | 默认参数在函数定义期把颜色绑死 | 默认值设 `None`，运行时从 `pal()` 取 |
| 某页正文比全篇小一号 | 窄栏塞不下就压字号 | 先改写文案、再调结构；`audit.py --all` 会跨页查出来 |
| 字号预检只查宽不查高 | 只看行宽，纵向溢出一眼看不见 | 预检要同时算「行数×行高」与容器高 |
